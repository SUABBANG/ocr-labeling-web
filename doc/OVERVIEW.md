# OCR 라벨링 웹 도구 — 프로젝트 설명

로컬 이미지 폴더의 OCR 라벨(박스 + 텍스트)을 브라우저에서 조회·수정하고,
LLM(GPT/Claude) 또는 로컬 모델로 라벨 초안을 자동 생성하는
**단일 사용자용 로컬 웹 앱**.

- 프론트: React + Vite, 박스 편집은 `react-konva`(canvas)
- 백엔드: Python + FastAPI (정적 프론트 서빙 + 파일 IO + 모델 실행)
- 저장소: 파일시스템 (DB·인증 없음). 모델 초안은 사람이 검수하는 것을 전제.

---

## 1. 개념: 프로젝트

폴더 경로를 매번 입력하는 대신 **프로젝트** 단위로 관리한다.

- 프로젝트 = `{제목, 설명, 데이터 폴더 경로}`
- 첫 화면 = 프로젝트 카드 목록(제목·설명·폴더·진행률 바). 카드 클릭 → 라벨링 화면 진입
- `＋ 새 프로젝트`로 생성, 카드에서 편집·삭제(데이터 폴더는 유지)
- 서버 루트 `projects.json`에 저장(폴더 경로가 서버 기준이라 서버에 저장)
- 카드 진행률 = 폴더 이미지 total/done 집계

## 2. 데이터셋 형태

이미지와 라벨은 **형제 폴더** 구조를 가정한다.

```
<데이터 폴더>/
  images/   img001.png, 문서_1.jpg ...      # 원본 이미지 (png/jpg/bmp/tif/webp)
  labels/   img001.json, 문서_1.json ...     # 이미지와 동일 stem, 없으면 자동 생성
```

라벨 파일 = 이미지당 JSON 하나:

```json
{
  "image": "문서_1.jpg",
  "width": 892,
  "height": 1253,
  "source": "manual",        // "manual" | "gpt" | "claude" | "local" (초안 출처)
  "done": false,             // 검수 완료 여부
  "words": [
    {
      "id": "w1",
      "text": "예시텍스트",
      "poly": [[x1,y1],[x2,y2],[x3,y3],[x4,y4]],  // 4점 quad, 좌상단→시계방향, 픽셀 정수
      "kind": "text",         // "text"(기본, 생략 가능) | "cell"(테이블 셀, 텍스트 없음)
      "script": "printed"     // 텍스트만: "printed"(기본) | "handwriting". 없으면 printed
    }
  ]
}
```

- **지오메트리**: 4점 quad 폴리곤 `poly` (일반적 OCR 라벨 관례). 축정렬 사각형은
  네 점이 직사각형인 특수 케이스. 회전/사다리꼴 박스도 표현 가능.
- **`kind`**: `"text"`(텍스트 있음) 또는 `"cell"`(테이블 셀, 텍스트 없이 영역만). 없으면 텍스트로 간주.
- **`script`**(텍스트 박스): `"printed"`(인쇄, 기본) 또는 `"handwriting"`(필기). 단어패널 `인`/`필` 버튼으로 전환. 없으면 인쇄로 간주.
- **`id`**: 편집 추적용. 신규 박스는 임시 id, **저장 시 배열 순서대로 `w1..wN` 재번호**되어 id가 순서를 반영한다. 드래그로 순서를 바꾸면 저장 후 id도 그 순서를 따른다.
- **`done`**: 검수 완료 플래그. 이미지 리스트 체크박스/진행률에 사용.
- 저장 = 파일 전체 덮어쓰기(부분 patch 없음). 단일 사용자라 충돌 처리 불필요.
- 경로 안전: 이미지/라벨 접근은 입력 폴더 하위로 제한(traversal 차단).

> 기존 `labels/` 형식이 다르면 `backend/labels.py`의 read/write 어댑터만 교체.

## 3. 화면 & 편집 기능 (라벨링 화면)

```
┌ [← 프로젝트] 제목 · 현재이미지 ────────[텍스트|테이블셀] [엔진▼][모델실행][저장]
│                                          [＋그리기][편집:bbox][↶취소][모두삭제][단축키] ┐
│ ┌ 이미지리스트 ┐ ┌ 캔버스(이미지+박스) ─────┐ ┌ 단어패널 ┐ │
│ │☑ img ● ×    │ │   줌/팬, 박스 편집         │ │ text edit │ │
│ │☐ img   ×    │ │                            │ │ ［셀］     │ │
│ └─────────────┘ └────────────────────────────┘ └───────────┘ │
└───────────────────────────────────────────────────────────────┘
```

### 라벨링 모드 (텍스트 / 테이블 셀)
- 모드 탭 `[텍스트][테이블셀]`로 전환. **현재 모드의 박스만** 캔버스·단어패널에 표시·편집·생성.
- 텍스트=파랑, 셀=주황. 셀은 단어패널에서 `［테이블 셀］`로만 표시(텍스트 입력 없음).

### 박스 편집
- 선택: 클릭. 이동: 박스 전체 드래그. 삭제: `Delete` 또는 단어패널 `×`.
- 신규: `＋그리기` 켜고 빈 영역 드래그(현재 모드 종류로 생성).
- **편집 모드 2종** (단축키 `B`, 툴바에 현재 상태 `편집: □ bbox / ◇ poly` 표시):
  - **bbox**: 꼭짓점 드래그 시 반대 코너 고정, 축정렬 사각형 유지
  - **poly**: 꼭짓점 하나만 독립 이동(자유 변형)
- 텍스트: 단어패널 인라인 입력. 각 텍스트 앞 `인`/`필` 버튼으로 인쇄/필기 지정(기본 인쇄).

### 줌 / 팬
- 줌: 마우스 휠(커서 기준, 0.1x~10x)
- 팬: **스페이스+드래그** 또는 **Ctrl+드래그**(박스 위에서도 동작)
- 리셋: `F`(화면 맞춤) / `1`(100%)
- 라벨은 항상 원본 이미지 픽셀 좌표로 저장(화면 변환은 Konva Stage가 처리)

### 실행 취소 (Undo)
- `Ctrl+Z` 또는 `↶ 취소` 버튼. 히스토리 스택(최대 100).
- 대상: 박스 추가·삭제·전체삭제·드래그(이동/리사이즈)·텍스트 편집·모델 실행.
- 드래그는 1회, 연속 텍스트 입력은 1스텝으로 묶음. 이미지 전환 시 히스토리 초기화.
- 입력창 타이핑 중 `Ctrl+Z`는 브라우저 기본 텍스트 취소.

### 기타
- **이미지 삭제**: 리스트 `×` → 이미지 + 라벨 파일 삭제(confirm)
- **박스 전체 삭제**: `모두 삭제` → 현재 모드 박스 일괄 삭제(confirm)
- **완료 체크**: 리스트 체크박스 / `C` 토글, 상단 진행률 `완료 N / M`
- **저장**: `Ctrl+S` 또는 `저장`(명시적 저장, 실수 방지). 초안 자동저장 안 함.

### 단축키 (기본값, 설정에서 변경 가능 — localStorage 저장)
| 키 | 동작 | 키 | 동작 |
|---|---|---|---|
| `↑`/`↓` | 이미지 이전/다음 | `F` | 화면 맞춤 |
| `Enter` | 텍스트 편집 | `1` | 100% 배율 |
| `Esc` | 취소/선택해제 | `C` | 완료 토글 |
| `Delete` | 박스 삭제 | `B` | 편집모드 bbox/poly |
| `N` | 신규 박스 | `Ctrl+Z` | 실행 취소 |
| `Ctrl+S` | 저장 | `Space`/`Ctrl`+드래그 | 이미지 이동(팬) |
| `R` | 모델 실행 | | |

## 4. 모델 실행 (라벨 초안 생성)

`POST /api/model?...&engine=<llm|local>` — 결과는 항상 `labels/<stem>.json`에 초안 저장 후
반환(`source` 표기). 프론트에서 검수·수정·재저장.

### 엔진 A: LLM (GPT / Claude)
- 이미지를 비전 모델에 보내 단어 단위 텍스트 + bbox를 JSON으로 받음 → 직사각형 poly로 변환
- 프로바이더: env `LLM_PROVIDER=claude|gpt`, 키 `ANTHROPIC_API_KEY`/`OPENAI_API_KEY`(`.env`)
- SDK 직접 호출, 래퍼 프레임워크 없음

### 엔진 B: 로컬 모델 (검출 → 인식)
2단계 파이프라인:
1. **검출** — `model/det/`의 검출 모델(PyTorch) → 단어 박스 (`backend/detection/`)
2. **후처리 패딩** — 각 박스를 우/하단으로 약간 넓힘(env `BOX_PAD_X`/`BOX_PAD_Y`, 높이 비율, 경계 clamp)
3. **인식** — `model/rec/`의 인식 모델(Paddle) → 각 박스 crop의 텍스트

**torch ↔ paddle 프로세스 분리 (중요)**: 두 GPU 휠이 각각 cuDNN 9를 번들해 같은 프로세스에서
동시 로드가 안 된다(`WinError 127`). 그래서 검출(torch)은 **메인 프로세스**, 인식(paddle)은
**상주 워커 서브프로세스**에서 실행하고, 워커는 torch import를 차단(paddleocr가 modelscope 경유로
끌어옴)한다 → 둘 다 GPU 사용 가능. 디바이스: 검출 CUDA 자동, 인식 `REC_DEVICE`(빈 값=자동 GPU).

- 무거운 의존성(torch/paddleocr/scipy/opencv)이라 **선택적 설치**(`requirements-local.txt`).
  미설치 시 `engine=local`은 501, 실행 오류는 502(메시지 포함).
- 좌표 정확도는 완벽하지 않음 → 초안, 사람 검수 전제.

## 5. 백엔드 구조 & API

```
backend/
  app.py          # 메인 (FastAPI 라우팅)
  config.py       # .env 로딩 + 프로바이더/모델 경로/패딩/디바이스
  projects.py     # 프로젝트 CRUD (projects.json)
  labels.py       # 이미지 스캔 + 라벨 IO + 경로 안전
  llm/            # LLM 엔진 (Claude/GPT)
  detection/      # 검출 모델 (torch) — arch/전처리/후처리 + detector
  recognition/    # 인식 모델 (paddle) — 워커 서브프로세스 관리
  pipeline.py     # 로컬 엔진: 검출 → 패딩 → 인식
```

| Method | Path | 설명 |
|---|---|---|
| GET | `/api/projects` | 프로젝트 목록(+진행률) |
| POST/PUT/DELETE | `/api/projects[/{id}]` | 프로젝트 생성/편집/삭제 |
| GET | `/api/images?folder=` | 이미지 목록(+라벨 존재·done) |
| GET/DELETE | `/api/image?folder=&name=` | 이미지 바이트 / 이미지+라벨 삭제 |
| GET/PUT | `/api/label?folder=&name=` | 라벨 조회 / 덮어쓰기 |
| POST | `/api/model?folder=&name=&engine=` | OCR 실행 → 초안 저장·반환 |

실행/설치는 [../README.md](../README.md) 참고.
